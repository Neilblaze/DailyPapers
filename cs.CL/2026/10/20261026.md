### Heard Enough to Act: Early Tool Calling in Spoken Dialogue Systems
- **Arxiv ID**: http://arxiv.org/abs/2610.34653v1
- **DOI**: None
- **Categories**: **cs.CL**, eess.AS
- **Links**: [PDF](https://arxiv.org/pdf/2610.34653v1)
- **Published**: 2026-10-26 00:34:30+00:00
- **Updated**: 2026-10-26 00:34:30+00:00
- **Authors**: Yizhou Peng, Chen Chen, Donghang Wu, Hexin Liu, Eng Siong Chng
- **Comment**: Submitted to ICASSP 2027
- **Journal**: None
- **Summary**: Latency-sensitive spoken agents must know not only which tool to call, but also when they have heard enough to act. Waiting for the turn to complete delays execution even when the request is already actionable. However, neither existing spoken agents nor spoken dialogue corpora define the earliest point at which a request becomes actionable. We introduce a synthetic spoken-dialogue pipeline that provides earliest-actionable-point supervision, marking when the observed speech grounds a tool and its required arguments. Through controlled task generation, speech synthesis and alignment, and gated annotation, we construct 26,694 dialogues totaling 786 hours across 48 domains, with disjoint training and test argument values. We additionally create an audio rendering of $τ^2$-bench for external evaluation. We train an omni-modal language model on this corpus, enabling causal, chunk-level decisions and partial-transcript generation for downstream call completion. The model achieves tool-state macro-F1 scores of 0.48 and 0.47 on held-out dialogues and the external benchmark, respectively. For correct calls, the estimated mean lead over a turn-end cascade, using the same formatter, is 1.8-2.0 seconds in-domain and 1.1 seconds on $τ^2$-bench. These results demonstrate a data-driven path toward spoken agents that act while listening. We will open-source the pipeline and the training scripts.

### Agent Memory as Recommendation: Recommender-System Design for Long-Term Memory of LLM Agents
- **Arxiv ID**: http://arxiv.org/abs/2610.34673v1
- **DOI**: None
- **Categories**: **cs.IR**, cs.AI, cs.CL
- **Links**: [PDF](https://arxiv.org/pdf/2610.34673v1)
- **Published**: 2026-10-26 01:05:20+00:00
- **Updated**: 2026-10-26 01:05:20+00:00
- **Authors**: Xinyu Zhang, Weiwei Sun
- **Comment**: 12 pages, 3 figures, 8 tables
- **Journal**: None
- **Summary**: Large language model (LLM) agents that serve users across many sessions must choose, for every request, the few stored memories that enter a limited context window. This choice largely decides whether the agent answers correctly, and it runs on every request at Web scale. This selection faces three challenges: a large and growing store, a per-request cost budget, and multi-session questions that need all of their evidence. Many memory systems build notes or graphs with hundreds to thousands of LLM calls per history, and each is designed on its own, so it is unclear which component yields the accuracy. These challenges mirror the properties of recommendation, so we formalize agent memory as budgeted slate recommendation, with the request as the user, stored memories as items and the context window as a slate. The formalization places memory systems in one design space of recommender cascades and factorizes accuracy into the completeness that each stage controls. Guided by it, we propose AgentMemRec, which adapts candidate generation, learning to rank and slate construction from recommender systems and selects memories without any LLM call. On multi-session questions of LongMemEval, AgentMemRec outperforms memory and context-selection methods, including A-Mem, HippoRAG 2, DynamicRAG and T-Mem, by 10 to 31 points of accuracy. It matches an LLM reranker that makes 64 calls per query at 3.2 times lower serving cost, and on LoCoMo it outperforms Mem0 and Zep without any LLM call at write time. The factorization attributes the gains to slates that more often hold all of the evidence, so recommender-system design offers an effective and efficient foundation for the long-term memory of LLM agents.



### Knowing When the Evidence Is Enough: Requirement-Directed Search with Horn-Closure Certificates
- **Arxiv ID**: http://arxiv.org/abs/2610.34684v1
- **DOI**: None
- **Categories**: **cs.IR**, cs.AI, cs.CL
- **Links**: [PDF](https://arxiv.org/pdf/2610.34684v1)
- **Published**: 2026-10-26 01:20:18+00:00
- **Updated**: 2026-10-26 01:20:18+00:00
- **Authors**: Xinyu Zhang, Weiwei Sun
- **Comment**: 12 pages, 2 figures, 5 tables
- **Journal**: None
- **Summary**: After each Web search, a search-augmented model must decide whether its evidence suffices: answer, search again, or abstain. Prevailing systems leave this to holistic model judgement, which can accept a context naming every entity yet lacking one required fact. We instead make sufficiency structural: a per-query requirement hypergraph states which facts jointly yield another fact. This raises two challenges: deriving requirements from the question alone, and linking each requirement to passages about the right entity. Certify therefore decomposes the question, searches per requirement, and accepts links only after entity checks. Horn closure over the links yields a certificate, the minimal sufficient passages and their derivation, or an abstention naming open requirements. Given correct retrieval, requirements and links, the decision is sound, and complete up to the entity check. Pooled over three corpora with unanswerable twins, Certify decides significantly more accurately than search agents, graph retrieval and sufficiency judges in default configurations. On the same evidence, it matches a proprietary model's sufficiency label without an additional model call. Over 21M Wikipedia passages, entity checks add 4 to 13 points of decision accuracy where gold evidence exists. Finally, answers from its certificate are 80% correct, against 57% from all retrieved passages.

- **Journal**: None
- **Summary**: An agent that truly knows and acts on behalf of its user has been a long-standing promise of AI assistants. Computer-use agents bring this promise within reach by capably executing fully specified tasks across apps. However, real-world user requests are often underspecified. To act correctly for the particular user, an agent must infer some missing information from the user's activity history and ask for other information that only the user can provide, without making unsupported assumptions or burdening the user with unnecessary questions. We present iPrefBench, a benchmark for evaluating the infer and ask capabilities of personal mobile-use agents in an executable iOS environment with an interactive simulated user. Our findings highlight a challenge for personalized agents in knowing what to infer and when to ask. We hope that iPrefBench can serve as a valuable testbed for building agents that know their user and work with them.

### DecisionTraceBench: Tracking Decision-Critical Information in Multi-Party Spoken Conversations

- **Comment**: Project repository: https://github.com/QFIN-tech/DecisionTraceBench
- **Journal**: None
- **Summary**: In high-stakes domains such as finance, critical information evolves through multi-party interaction. Recovering these changes and their sources is fundamental to reliable speech understanding. Existing speech benchmarks focus on transcription, local understanding, and turn-level state prediction, leaving joint decision evolution across speakers insufficiently evaluated. We introduce DecisionTraceBench, a speech state-tracking benchmark for Decision-Critical Information State Tracking (DCIST). It jointly evaluates decision event sequences, speaker attribution, scope, and temporal evidence, using trajectory-level F1 to measure complete event-chain recovery. Our dataset comprises Chinese financial dialogues involving two to four speakers, with 100.39 hours of synthetic audio and 8.61 hours of human-performed recordings. Ablations with speaker-labeled reference scripts and no temporal localization requirements yield a maximum score of only 38.72%. Audio perturbation experiments further show that overall transcription error rates do not adequately reflect complete trajectory recovery. These findings reveal limitations in jointly understanding information provenance and state evolution, providing a benchmark for evaluating decision-process understanding and decision traceability in high-stakes speech applications.

- **Summary**: Low-Rank Adaptation (LoRA) has emerged as the dominant paradigm for parameter-efficient fine-tuning of large language models. - **Summary**: Knowledge editing aims to update outdated or incorrect knowledge in large language models without full retraining. ### Natural Jammers: When Non-Robust Features Become Antagonistic
- **Arxiv ID**: http://arxiv.org/abs/2610.34785v1
- **DOI**: None
- **Categories**: **cs.CV**, cs.CL
- **Links**: [PDF](https://arxiv.org/pdf/2610.34785v1)
- **Published**: 2026-10-26 03:29:27+00:00
- **Updated**: 2026-10-26 03:29:27+00:00
- **Authors**: Jiaming Zhang, Fuyao Zhang, Pengjun Xie, Wei Yang Bryan Lim
- **Comment**: NeurIPS 2026 Spotlight
- **Journal**: None
- **Summary**: Deep neural networks are known to rely on non-robust features that align poorly with human perception. Prior work has largely framed these features as opportunistic shortcuts that help standard models on clean data. We show instead that non-robust cues can be antagonistic: they can act as Natural Jammers that actively mislead standard models on clean, unmodified images. Using disagreement between a standard model and robust models as an analysis lens, we identify a Jammed Set on which robust models outperform standard models. Crucially, we uncover a Substitution Paradox: while individual jammers are fragile to geometric shifts, the aggregate prevalence of jamming remains approximately stable and is redistributed rather than eliminated under such transformations. Our results reframe natural non-robustness as a failure field over the empirical model-data geometry: one that redistributes rather than disappears under small transformations.

- **Summary**: Language models now answer questions alongside other claims: a note in the system prompt, a message from another agent, their own earlier answer. - **Summary**: Much of the information needed for data analysis is buried in text columns: an analyst may infer customer frustration from complaint text and use it to explain resolution time. - **Summary**: LLM post-training often optimizes multiple objectives with unequal priorities, such as correctness and reasoning efficiency.
