- **Comment**: 18 pages, 2 figures, 6 tables. Work in progress: benchmark design and protocol; results to be added in a later version

- **Summary**: Agent Skills, file-based packages of procedural knowledge that a coding agent can discover and load on demand, are now shipped by every major agent harness, yet the evidence for how much they help comes almost entirely from settings in which the right Skill is hand-picked for the task and the agent starts from a blank slate. The evaluation is in progress: results will be added once the runs are complete, and the task suite, results and analysis will continue to be updated on a rolling basis.

- **Summary**: Checking whether a generated sentence is supported by its source document is a standard safeguard for AI-written text, and the strongest published checkers are single models. The test split was run once, on an engine frozen before the first test claim, under a stopping plan committed in advance. We release per-claim predictions and the scoring script.



### Thinking Harder Doesn't Lead to Better Choices: Reasoning Effort Increases the Confidence but Not the Correctness of LLM Shopping Agents

- **Links**: [PDF](https://arxiv.org/pdf/2611.22033v1)
- **Published**: 2026-11-17 00:55:58+00:00
- **Updated**: 2026-11-17 00:55:58+00:00
- **Authors**: Adi Krishnamoorthy, X. Y. Han
- **Comment**: None
- **Journal**: None
- **Summary**: Large language models (LLMs) are increasingly deployed as autonomous shopping agents that process multimodal product listings (consisting of visual and text data) and recommend purchases on behalf of consumers. Naturally, one might assume that models with more thinking power would make higher-quality purchasing decisions. To test this belief, we ask two questions about such agents: does asking a model to think harder make it choose better products, and does the confidence it reports tell us the likelihood it may be wrong? We benchmark ten frontier models on three product-choice benchmarks built from WebShop, Amazon's SQID and Wayfair's WANDS platforms to see if LLMs with more thinking power actually make better-quality product purchase decisions. We also measure the calibration of these models (how well their reported confidence percentage matches their true correctness percentage) in these tasks and show that most models are not well-calibrated at every effort level. We also find that errors are strongly shared: when one model errs in a task, several others tend to err on that same task. Furthermore, on tasks where several models all err, a large number of them pick the same wrong product.

- **Summary**: Improving the quality, clarity, and flow of long documents remains a challenging problem in NLP, as human editing typically occurs through iterative refinement rather than a single-pass rewrite. - **Summary**: In mixture-of-experts (MoE) language models, a token is routed to a sequence of experts across layers. ### Option-GRPO: Hierarchical RL Against AI Slop in Code Generation for Unseen SDKs
- **Arxiv ID**: http://arxiv.org/abs/2611.23633v1
- **DOI**: None
- **Categories**: **cs.SE**, cs.CL, cs.LG
- **Links**: [PDF](https://arxiv.org/pdf/2611.23633v1)
- **Published**: 2026-11-17 23:52:34+00:00

- **Authors**: Prashank Kadam

- **Journal**: None
- **Summary**: Large language models increasingly produce AI slop in generated code: verbose, redundant, non-idiomatic implementations that pass functional checks but bloat codebases. The problem compounds on SDKs released after the model's training cutoff, where the model has neither idiomatic priors nor compositional understanding. We present Option-GRPO, a hierarchical reinforcement learning framework that adapts a code LLM to an unseen SDK from its source code alone, without human-written usage examples or test cases, and that explicitly optimizes for both functional correctness and code elegance.
