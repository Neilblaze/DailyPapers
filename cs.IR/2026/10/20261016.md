### Reasoning Reranking with Semantic IDs as the Sole Item Representation
- **Arxiv ID**: http://arxiv.org/abs/2610.22797v1
- **DOI**: None
- **Categories**: **cs.IR**, cs.CL, cs.LG
- **Links**: [PDF](https://arxiv.org/pdf/2610.22797v1)
- **Published**: 2026-10-16 01:21:47+00:00
- **Updated**: 2026-10-16 01:21:47+00:00
- **Authors**: Zhenwei Tang, Jintao Liu, Di Bai, Xidong Wu, Xinwu Cheng
- **Comment**: 30 pages, 3 figures. Code: https://github.com/lilv98/ReRankID ; data: https://huggingface.co/datasets/lilvjosephtang/ReRankID
- **Journal**: None
- **Summary**: Reasoning rerankers write a rationale before ranking a candidate slate, and existing systems read item metadata to do so, even though generative recommenders increasingly represent items as compact Semantic IDs (SIDs). Ranking from SIDs alone has two appeals: SID prompts are far shorter than the matched item text, and although item codes are fixed from content, the backbone learns their token embeddings in part from user-item interaction sequences, so the tokens can carry behavioral signal that item text lacks. That training targets next-item generation, and whether it supports ranking a supplied slate from SIDs alone is untested. We build ReRankID, a controlled testbed in which models reason and rank from a history and slate shown only as SIDs, varying item rendering, history length, and slate size one at a time. On this testbed, such models often copy the input order instead of reranking, and readable metadata does not repair the failure. We compare supervised fine-tuning, rejection-sampled self-training, on-policy distillation, and verifier-based reinforcement learning as post-training methods and find that they elicit the missing behavior. The strongest post-trained model, the 8B model trained with a graded ranking reward, gives the best SID-only ranking and matches strong text-reading LLMs whose prompts are about 20x longer. It ranks above random with no history at all, where a caption-reading reference does not, and it keeps its gains at long histories, where text prompts pass 50k tokens and the caption-reading reference stops improving. In a paired rationale audit, this model argues trade-offs better than that reference but describes items less accurately. The common post-training methods we test thus elicit ranking from SIDs but not faithful item descriptions, which calls for post-training that improves the reasoning itself, not only the ranking it produces.



### Code Skill Server: A Large-Scale Search Engine for Code Generation Skills
- **Arxiv ID**: http://arxiv.org/abs/2610.23186v1
- **DOI**: None
- **Categories**: **cs.SE**, cs.IR
- **Links**: [PDF](https://arxiv.org/pdf/2610.23186v1)
- **Published**: 2026-10-16 09:23:51+00:00
- **Updated**: 2026-10-16 09:23:51+00:00
- **Authors**: Xiaoyong Li, Haolong Li, Dongliang Xu, Haoyu Li, Yifan Wang, Jingyuan Shi, Yanghua Wang, Yanbin Sun, Shidong Pan, Yue Yao
- **Comment**: None
- **Journal**: None
- **Summary**: Agent skills have proven to be an effective technique for improving agent ability on specific tasks, including software engineering, natural science, and mathematics. During such a process, using agent skills often involves manually discovering and organizing skills from heterogeneous sources, while existing skill retrieval methods mainly focus on selecting relevant skills from established skill libraries. However, with the rapidly increasing number and variety of reusable agent skills, manually searching for relevant skills across heterogeneous sources is becoming impractical at scale. In this paper, we introduce the Code Skill Server (CSS), a large-scale search engine for finding the most useful code generation skills for a target task. CSS consists of a skill server that incrementally collects and indexes publicly available code generation skills from multiple sources, with 993 skills included in the corpus used in this work. Extensive experiments across different retrieval methods and code generation benchmarks show that the best CSS configuration improves Pass@1 by up to 13.91% and consistently improves all evaluated models by at least 4.21% in the cross-model evaluation. These results demonstrate that CSS can effectively search for and serve relevant skills, improving code generation quality and enhancing models' code generation capabilities. Code and the CSS-993 corpus are available at {https://github.com/haoyuli-sdu/CodeSkillServer}.



### Jev-as-a-Judge for Brazilian Portuguese Information Retrieval: Relevance Assessment and Reranking
- **Arxiv ID**: http://arxiv.org/abs/2610.23346v1
- **DOI**: None
- **Categories**: **cs.IR**
- **Links**: [PDF](https://arxiv.org/pdf/2610.23346v1)
- **Published**: 2026-10-16 11:52:46+00:00
- **Updated**: 2026-10-16 11:52:46+00:00
- **Authors**: Leandro Carísio Fernandes, Jayr Pereira
- **Comment**: None
- **Journal**: None
- **Summary**: This study investigates Jev, a System One model designed for fast, structured decision-making, in information retrieval. We use Jev-as-a-judge to generate relevance judgments for four Brazilian Portuguese IR collections covering different domains and compare them with the official relevance judgments of each collection. We also evaluate Jev as a reranker. For relevance assessment, exact agreement ranged from 52.9% to 64.9%, while quadratic weighted Cohen's kappa ranged from 0.52 to 0.82. Most disagreements involved adjacent relevance levels, with at least 94.5% of annotations matching exactly or differing by only one relevance level. Despite differences at the individual query--document level, Jev-generated qrels produced similar retrieval system rankings, with Kendall's tau ranging from 0.90 to 0.93 for NormasTCU and Ulysses-RFCorpus across the two evaluation metrics. For reranking, Jev reordered the top 1,000 BM25 candidates for each of the 50 Quati test queries, increasing nDCG@10 from 0.3329 to 0.6331 (+90.2%) and MRR from 0.6852 to 0.9033 (+31.8%). These findings support Jev as a relevance assessor and show improved ranking effectiveness over BM25 in the evaluated reranking setting.



### QD-Rec: Open-Ended Evolution of Recommendations via Quality-Diversity
- **Arxiv ID**: http://arxiv.org/abs/2610.23470v1
- **DOI**: None
- **Categories**: **cs.IR**, cs.AI, cs.LG, cs.NE
- **Links**: [PDF](https://arxiv.org/pdf/2610.23470v1)
- **Published**: 2026-10-16 13:49:22+00:00
- **Updated**: 2026-10-16 13:49:22+00:00
- **Authors**: Takashi Ishida, Taro Makino, Issa Sugiura
- **Comment**: None
- **Journal**: None
- **Summary**: Open-ended search combined with foundation models has produced advances such as faster algorithms, new results on open mathematical problems, and self-improving agents. We extend this paradigm to recommendation for decision-making, focusing on decisions where the set of possible choices is fixed but the reasons for choosing them are not. In high-stakes decisions, e.g., which company to acquire or which customer to target, comparing diverse, well-reasoned options can be more useful than a single ranked list. We formalize open-ended recommendation as building a diverse, high-quality set of recommendations, each an item together with a hypothesis, a natural-language reason why the item fits the needs of a decision maker. We propose QD-Rec, a quality--diversity method that selects items with a contextual bandit and generates hypotheses with a foundation model from earlier ones kept in an archive as stepping stones. A new recommendation enters the archive if it is novel or better than its nearest neighbor. Across M&A, customer targeting, and paper and book recommendation, QD-Rec gives the highest mean quality and builds the largest archive in most settings.



### LSNR: Learned Sparse News Recommendations with Attentive User Modeling
- **Arxiv ID**: http://arxiv.org/abs/2610.23510v1
- **DOI**: None
- **Categories**: **cs.IR**
- **Links**: [PDF](https://arxiv.org/pdf/2610.23510v1)
- **Published**: 2026-10-16 14:19:13+00:00
- **Updated**: 2026-10-16 14:19:13+00:00
- **Authors**: David Vos, Andrew Yates, Maarten de Rijke
- **Comment**: 10 pages, 3 figures, 9 tables. Accepted at SIGIR-AP 2026
- **Journal**: None
- **Summary**: Current learned sparse approaches for recommender systems, such as STAR, represent a user by concatenating their interaction history into a single query string. For news, this creates two bottlenecks: concatenation collapses a user's distinct reading interests into one flat query, and, because news articles are long-form text, concatenating several news articles quickly overruns the context window of the language model used as backbone and forces quality-degrading truncation.   To address both bottlenecks, we introduce learned sparse news recommendations (LSNR). LSNR encodes each article independently and constructs a sparse user vector by combining learned, attention-based weighting of the per-article sparse representations with a dense-projected expansion at the user level. Experiments on the MIND and EBNeRD datasets show that LSNR significantly outperforms STAR, with these gains holding even in short-history settings where truncation is not a factor. Compared to state-of-the-art dense recommenders, LSNR is competitive in standard settings and it outperforms them when the user history is short. An ablation of the user encoder confirms that learned attention-based aggregation outperforms simpler pooling alternatives. Beyond effectiveness, an additional advantage of LSNR is that it serves from an index an order of magnitude smaller than an uncompressed dense baseline.



### Humanity's Last Choice: A Common Evaluation Standard for Generative Engine Optimization
- **Arxiv ID**: http://arxiv.org/abs/2610.23541v1
- **DOI**: None
- **Categories**: **cs.IR**
- **Links**: [PDF](https://arxiv.org/pdf/2610.23541v1)
- **Published**: 2026-10-16 14:35:42+00:00
- **Updated**: 2026-10-16 14:35:42+00:00
- **Authors**: Qianfeng Wen, Yifan Simon Liu, Difan Jiao, Junda Wu, Di Bai, Jintao Liu, Xidong Wu, Zhenwei Tang
- **Comment**: 19 pages, 2 figures. Project website: https://humanitylastchoice.org
- **Journal**: None
- **Summary**: Humanity's Last Choice describes the idea that the last choice people need to make is which AI system they entrust with the decisions that follow. These systems rely on external sources that content providers can edit through generative engine optimization (GEO) to increase source visibility and influence recommendations. Choosing among these systems therefore requires comparable evidence of how well they carry out user requests when exposed to GEO. Benchmarks have made progress in standardizing tasks, models, and metrics, but they often define their own spaces of GEO strategies and use different editing constraints. These differences can conflate gains from better optimization algorithms with those from greater freedom to edit sources, while making evaluation coverage difficult to compare across benchmarks. We therefore call for a common evaluation standard and propose a meta-taxonomy that describes where sources are edited, how they are edited, and what signals those edits target. Drawing on representative literature, we map existing strategies into a searchable space and outline a protocol for controlled comparisons with explicit coverage reporting. This provides a foundation for common leaderboards that can inform which systems people choose to rely on.



### Tool Recommendation for Multi-Step Agents: Finding Every Tool a Task Needs
- **Arxiv ID**: http://arxiv.org/abs/2610.23707v1
- **DOI**: None
- **Categories**: **cs.LG**, cs.IR
- **Links**: [PDF](https://arxiv.org/pdf/2610.23707v1)
- **Published**: 2026-10-16 16:30:38+00:00
- **Updated**: 2026-10-16 16:30:38+00:00
- **Authors**: Sam Partee, River Stevens, Thierry Damiba, Valerie Fanelle
- **Comment**: 11 pages, 3 figures, 5 tables
- **Journal**: None
- **Summary**: A multi-step agent task fails when a single tool it needs is missing, yet the tools an agent may need are too many to list: the roughly 8,200 tools on the platform we study have definitions that together exceed the context window of any model we evaluate. We present Tool Recommendation, a deployed system that gives an agent all of them, hundreds of times more than a typical MCP server exposes, through a fixed interface of three tools. It runs at the gateway between agent and tools, executing every call under the end user's own credentials and checking it against the user's consent for each service and the tools the agent may use. We evaluate it on both a public retrieval benchmark and billed end-to-end session cost. On ToolRet, Tool Recommendation places every tool a query needs in the top ten 57% more often than BM25, a lexical ranking that commercial tool search offers, and compares favorably with published systems up to nine times its size. In paired multi-step workflows, its first recommendation covered every required tool in 93% of Codex sessions, and against a fixed list of 100 tools it cut input tokens by 17% with Codex and 40% with Claude Code and the total bill in all 14 runs, by up to 40%, with no change in task completion.
